## Paper-vs-implementation discrepancies

Findings about CharacterBox's own paper describing behavior its own released appendix/code does not exercise. Not a modification made by this project — a verified gap in the anchor paper, kept here (not only in chat) so it survives into the thesis limitations/methods discussion. A related but distinct gap — this project's own controlled design never reproducing CharacterBox's steady-state Self Belief/Environment Belief updates, unlike the memory-module case below — is recorded in the "Components currently excluded" table further down this file, not repeated here.

### CharacterBox's memory module: paper claims relevance-based retrieval; its own appendix and code show recency-only

- **Paper claim** (Wang et al., 2025, §3.2 "Character"): "Characters, controlled by LLMs, use a memory module inspired by (Park et al., 2023), where each agent utilizes a vector database to record past actions and observations, **retrieving relevant information** to guide future behavior."
- **The paper's own contradicting evidence** (Appendix D.2, "Character Prompts"): every character-side prompt shown there — Action, Dialogue, Update Self-belief — references only "**recent memories**"/"**recent memory**," never "relevant memories."
- **Code verification** (this project's inherited `agents/character.py` and the real upstream `../CharacterBox/agents/character.py`, both checked directly): `_generate_reaction()`'s prompt template only ever references `{most_recent_memories}` — a pure recency window (`GenerativeAgentMemory._get_memories_until_limit()`, which walks `memory_stream[::-1]` and never consults relevance or importance). `{relevant_memories}` — built by `summarize_related_memories()`/`fetch_memories()`, the actual similarity+recency+importance retriever the paper's sentence describes — is never referenced by the character dialogue-generation prompt in either the real upstream source or this project's copy. That retrieval path exists in the underlying `langchain_experimental` dependency and is exercised only by the reflection subsystem (`pause_to_reflect()` → `fetch_memories()`), not by dialogue generation.
- **Not disclosed as a limitation**: CharacterBox's own Limitations section names three shortcomings (runtime efficiency, reward-model annotation data, constrained context window); this discrepancy is not among them.
- **Decision for this project**: preserve the implementation's actual behavior (recency-only Recent Memory field) as the faithful S baseline, per this project's own Hard Rule 2 requirement that S match "retained CharacterBox behavior" — behavior, not the paper's narrative description. Relevance-based retrieval is not built into S, U, or P: it is unrelated to the U/S/P context-structuring intervention (fails the `research-contract.md` §13 feature-decision test — does not help construct U/S/P, does not enforce equivalence, does not measure a declared outcome), and at this study's trial lengths (a handful of turns, a memory stream of at most a few entries per trial) a relevance ranking would almost certainly select the same items a recency window already selects, so building it would not be expected to change any actual generated output.
- **Related**: the 2026-08-30 "No-op importance scoring for controlled-trial memory" entry below independently found that the importance score CharacterBox's memory module *does* compute (a real, billed model call on every `add_memory()`) is never consulted by this same recency-only path either — a second, separate way the inherited memory module computes more than its own dialogue prompt actually uses.
- **For the thesis**: cite this as a specific, verified discrepancy between CharacterBox's description (§3.2) and its own released artifacts (Appendix D.2 + source code) when discussing the S baseline's fidelity — this project reproduced CharacterBox's actual behavior faithfully, not its unimplemented description.

## Reuse categories

Each relevant component must be classified as one of:

- **Copied:** substantially identical source code, apart from mechanical changes.
- **Adapted:** code derived from CharacterBox with meaningful modifications.
- **Reimplemented from concept:** independently written code following a general architectural idea; no substantial source expression copied.
- **Not reused:** inspected but deliberately excluded.

Calling something “inspired by” is not a substitute for identifying copied or adapted code.

## Components currently excluded

| CharacterBox component | Reason excluded from initial study |
|---|---|
| Narrator as authoritative world model in controlled trials | LLM-generated outcomes can become unverified later context and confound consistency; the English-only adapted Narrator is reserved for dynamic mode |
| Autonomous multi-agent simulation | Makes the context intervention harder to isolate; controlled single-turn trials come first |
| Extracted book/script scenes and source `chunk` passages | Licensing and pretrained-franchise contamination concerns; only sanitised generated scenes are used for development |
| `LocalLLM` and `CustomLLM` execution paths | Their source is now retained for fidelity, but these incomplete/unused runtime paths remain outside the initial provider and controlled study |
| Full live dynamic HumanPlayer run | Observation, gender, belief/synopsis, reaction, and mode-routing repairs are implemented, but the complete real-provider Narrator cycle still requires a successful rerun |
| Per-round Self Belief / Environment Belief updates in controlled trials | `update_self_belief()`/`update_env_belief()` are never called during controlled dialogue-only interaction (Hard Rule 6), so both fields render empty in the S/U/P prompt for every round of every controlled trial, not only the first. This differs from CharacterBox's own dynamic mode, where both fields start empty but are populated from round 2 onward by per-round belief updates — CharacterBox's steady-state, intended behavior for these two fields is not reproduced here. The exclusion is deliberate (isolating the U/S/P context-structuring intervention from autonomously-generated belief content that could otherwise diverge unpredictably across conditions), and it affects U, S, and P identically, so it does not confound the U/S/P comparison itself — but it is a genuine gap between this study's S baseline and CharacterBox's typical usage for these two fields specifically, distinct from the memory-relevance discrepancy above. |
